Подключение к PostgreSQL
Соединение - ресурс, связанный с сетью и состоянием сеанса БД.
Строка подключения - это набор параметров вида key = value, разделенные точкой с запятой.
Типовой набор включает в себя:
1. хост
2. порт
3. Database
4. username
5. password
Значения могут дополняться настройками таймаута, SSL, пула и другими параметрами.
Using и Await using
Using гарантирует вызов Disposable 
Await using используется для IAsyncDisposable и позволяет асинхронно освобождать ресурс, если библиотека предоставляет асинхронную модель освобождения
Connection pooling
открытие соединения приложений не обязательно обозначает каждый раз создание нового TCP сеанса до PostrgreSQL. Npqsql использует Connection pooling: закрытое через Dispose соединение обычно возвращается в pool, а следующий open может получить уже существующее физическое соединение

npgsqlDataSource - это специфичная точка входа
DataSource рекомендуется обычно создавать один раз на приложение, инкапсулирует конфигурацию и пул соединение. При это стандартный ADO.NET Connection API никуда не исчезает, DataSource может выдавать npgsqlConnection, а npgsqlCommand остается командой
Data Reader - фундаментальный способ чтения результатов в ADO.NET. Он работает последовательно, сначала курсор стоит перед первой строкой, затем read/Async переводит его на следующую доступную строку 
Преимущества Data Reader:
- потоковая модель. Документация описывает его как read-only, только для чтения, поток результатов. Это особенно полезно для больших выборок, когда не хочется копировать весь набор в память

Значения по типу
Методы 
get string
get date/time
get int
возвращают значение в конкретном .NET типе
Это делает код явным, но требует чтобы столбец соответствовал ожидаемому типу

```
var id = reader.GetInt32(0);var name = reader.GetString(1);var birthDate = reader.GetDateTime(2);
```
Чтение по имени проще понять, но обращение по индексу обычно дешевле и меньше зависит от поиска имени
Практический компромисс - заранее определить ordinals(порядковые номера) по имени затем читать по индексу
null и DbNull
SQLNull - это отсутствие значения. В .NET обычное null используется для ссылочных типов, но Data Reader исторически представляет отсутствие SQL значение через DbNull.value. По этому перед get string, get date/time, get int нужно проверить IsDbNull

Параметры и SQL Injection
SQl нельзя строить конкатенацией пользовательских строк. Параметры отделяют SQL код от данных
Опасная конкатенация  
```
var sql = $"SELECT id, name FROM students WHERE name = '{name}'";
```
Проблема возникает, когда значение name, может содержать специальные символы или фрагменты кода. В худшем случае это дает возможность изменить смысл запроса
Это и есть SQL Injection
Безопасный вариант  
```
await using var command = new NpgsqlCommand( "SELECT id, name FROM students WHERE name = $1", connection);
command.Parameters.AddWithValue(name);
await using var reader = await command.ExecuteReaderAsync();
```
Параметры предназначены для обозначения данных, а не для частей синтаксической структуры SQL. 
Нельзя надежно сделать SELECT * FROM $1, передав имя таблицы, как обычный параметр. Если имя таблицы/колонки должно быть динамическим, нужно использовать белый список допустимых идентификаторов или специальные механизмы "безопасного" акцентирования, предоставляемое конкретным драйвером
Типы параметров
npgsql старается вывести PostgreSQL тип из .NET. Во многих случаях этого достаточно, однако PostgreSQL имеет строгую типизацию и для некоторого типа(JSONb, специфические PostgreSQL типы), может потребоваться явное указание npgsqlDbType 
```
command.Parameters.AddWithValue( NpgsqlDbType.Jsonb, jsonText);
```
NpgsqlDbType - Npgsql-специфичное перечисление. DbType - более переносимый ADO.NET API. Выбор между ними зависит от того, насколько вам нужна переносимость между провайдерами.
